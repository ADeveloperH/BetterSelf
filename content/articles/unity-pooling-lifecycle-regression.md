## 优化目标

每次重开和切关重新创建车辆、角色，存在可减少的实例化与销毁。方案先把长乘客队列的逻辑数据与可见对象分开，再让角色和三种车型在同一游戏场景内复用。

这针对后续切关的对象创建成本，首次进入仍需要建池；提高稳定运行 FPS 不是直接目标。池保留各车型需求的高水位对象，会增加常驻内存。手机切关耗时还没有完整对照数据，不能用自动测试通过代替收益测量。

## 所有权比容器更重要

车辆池跟随游戏场景，按预制体分别存储。归还范围不能只看当前棋盘数组，因为停车、离场、隐藏或重新挂到其他父节点的车辆仍属于本轮借出对象。维护借出登记，退出场景时整体释放。

乘客也有自己的所有者登记；已经坐到车里、还在路上或从可见队列移除的乘客都要清理。切关先归还全部乘客，再归还车辆，避免子对象与旧座位引用带入下一关。

## 归还与再次租用必须恢复哪些状态

| 状态                        | 处理方式                                            | 忽略后的风险                             |
| --------------------------- | --------------------------------------------------- | ---------------------------------------- |
| 协程、Tween、序列和延迟回调 | 在对象复用前停止；为根序列/延迟调用建立明确取消目标 | 旧关卡回调移动车辆、再次出发或占用新车位 |
| 根和子节点的变换、启用状态  | 保存初始快照，复用前恢复                            | 停车缩放、隐藏车顶、箭头等状态残留       |
| 颜色、座位数、满员/行驶字段 | 恢复后按新关卡数据初始化                            | 新关卡一开始满员或错误离场               |
| 碰撞器、音源                | 恢复原状态                                          | 不可点击、碰撞丢失、残留声音             |
| 车位、车库、撤销、座位引用  | 清理旧管理器/对象引用                               | 操作到已销毁关卡或重复释放               |
| 粒子                        | 停止并清空；保留预制体约定的重新播放方式            | 上一关特效带入新关卡或复用后不再发射     |
| 取景、布局等外部消费者      | 确认输入只包含当前关卡的稳定实体                    | 看似对象已重置，首帧镜头仍异常           |

不要只检查 `SetActive(false)` 和业务字段；要检查谁仍可能在稍后写入这个对象，以及谁缓存了它的派生结果。

## 一次由池化暴露的相机跳变

用户反馈切关后整个场景突然平移或缩放。车辆本体的位置恢复后问题仍可能发生，因为取景代码收集车辆下所有 `Renderer.bounds`，其中包含尾部烟雾的 `ParticleSystemRenderer`。

历史复现中，烟雾 Renderer 在没有活粒子的情况下仍可保留上次停车/离场的世界边界。旧车在远处的边界被纳入新关卡取景，相机因此后退或移动。恢复 Transform、看到 `particleCount == 0` 都不足以保证立即取得正确边界；此前尝试处理局部边界仍未完整解决首帧问题。

修复分成两个职责：

- 构图只从车辆 `MeshRenderer` 实体模型计算，不让动态特效定义关卡尺寸。
- 车辆归还时停止并清空缓存到的 ParticleSystem，避免旧特效残留。再次激活保持原有 Play On Awake 行为，并验证行驶中的发射继续正常。

对其他项目，重点是“取景输入应是稳定实体”的原则。若角色使用 SkinnedMeshRenderer，应纳入该项目的实体模型规则；不能机械复制只接受 MeshRenderer 的过滤器。

## 怎样设计能检出原问题的回归

普通的“重开后看起来正常”很难稳定发现问题。复现先把所有车辆移到棋盘外，施加停车缩放，隐藏可拆部件，等待一次渲染更新，让烟雾有机会保留旧边界，再加载同一关卡。

测试同时覆盖离场后隐藏并从活动数组移除的车辆；比较车辆复用身份、实体几何、画面裁切、新关卡加载完成的首帧及之后三帧的相机。

历史图形 PlayMode 回归共 11 项：视口/镜头 5 项、车辆复用 4 项、真实特效 2 项，均通过。该构造测试中修复后相机误差在 0.01 世界单位内，回收时旧粒子清零，十座车重新行驶仍能发射烟雾。这是自动回归范围，不是所有手机场景都已验证。

此前数据缓存/映射与网格 EditMode 78 项、完整玩法 PlayMode 46 项也通过。这些历史测试运行有交集，不能把多轮运行数量直接相加宣称更多独立覆盖。

## 真机测试用例

| 用例            | 操作                               | 观察点                                                 |
| --------------- | ---------------------------------- | ------------------------------------------------------ |
| 首次/暖重开对照 | 冷启动进入一次，再连续重开至少三次 | 分别记录切关时间、峰值帧耗时、分配和内存               |
| 行驶中重开      | 点击出车，在转弯或停车动画中重开   | 无旧车移动、无旧回调占用新车位，首帧背景稳定           |
| 上车/满员重开   | 上车中及满员离场前分别重开         | 新座位为空、进度归零，无旧乘客残留                     |
| 离场隐藏后重开  | 等车完全离场隐藏再重开             | 车辆外观、颜色、碰撞与烟雾恢复，镜头无跳动             |
| 道具/撤销/复活  | 完成相关流程后重开，再正常出车     | 旧引用清理，交互与状态一致                             |
| 连续切关与退出  | 连续通过多关，再退出游戏场景并进入 | 对象数量达到需求后稳定，离场对象仍可归还，退出后不残留 |

原资源没有覆盖的车库玩法，需要补真实车库关卡回归；自动引用清理测试不能代替其动画体验验证。环境、停车位和关卡管理器仍逐关重建，不属于本次池化范围。

## 下次复用时保留什么

保留对象所有权登记、状态清单、清理顺序和能重现旧问题的测试模式。容量上限应根据当前资源重新统计，不能沿用旧关卡数量下的高水位。性能收益用手机前后对照补充，业务类和池大小留在原项目，不当成跨项目固定模板。

回到[性能优化总览](#/article/unity-mobile-performance-playbook)比较：局部数据缓存、减少显示对象与车辆复用分别解决不同阶段的成本。
