# 笔记整理与网站结构草案

> 本文保留结构规划 / 本地验证阶段的记录。当前0.2.0版本的内容范围与发布检查见[发布说明](RELEASE_0.2.0.md)。

日期：2026-10-22。状态：基于全目录盘点的第一版草案；网站入口与内容模型已完成本地实现和检查，尚未发布；正文整理与批量迁移仍未开始。

## 目标与本轮结果

把历史笔记整理成便于查找、阅读和更新的笔记库；面试练习、个人复习各有独立入口。默认打开笔记库，普通笔记不因被阅读或收藏而自动成为复习任务。

本轮只读盘点了有道云笔记的全部目录与标题：**139 个文件夹、494 篇笔记**。含根目录共核对 140 个目录列表，分页与目录读取已补齐，失败项为 0。文件名后缀为 493 篇 `.note`、1 篇 `.md`；文件名后缀不是正文格式完整性的证明。

本地已产出逐篇分类草案和标题重复候选。**分类依据只有标题及原目录，没有在本轮读取正文；没有执行重命名、合并、删除或公开发布。**

包含原始路径和私人标题的清单位于被 Git 忽略的 `.artifacts/youdao-inventory/`，只留在本机。此文档不包含完整原始清单。

## 盘点揭示的问题

- 最大的三个来源是 Study（163 篇）、我的资源（105 篇）、知识库（70 篇），合计 338 篇，约占全部笔记的 68%。Study/Unity 下有 69 篇，可作为 Unity 专题的主要输入。
- 同一主题散落于学习目录、知识库、面试资料及问题记录中。目录名同时混用了技术领域、用途、项目、时间和内容状态，直接照搬会延续查找困难。
- 规范化空格与常见分隔符后发现 **18 组标题重复候选，涉及 42 篇**。候选包括 VSCode 快捷键、LiveData、Room、App 启动流程、事件分发、内存优化和启动优化。同名可能只是主题相同；没有正文证据时不判定重复。
- 「我的资源」主要是 Android 面试相关资料，但其中有大量基础概念、框架说明和工具文章。原目录属于面试资料，不等于每篇内容都适合直接成为一道题。
- 周报、会议、需求、述职、个人备忘和技术总结并存；它们的整理方式和公开范围不同，需要先分流。
- 当前标题初分仅为 366 篇给出待复核主题方向，128 篇保留“待归类”；296 篇的笔记类型仍待确认。信息不足时保留待确认，避免把猜测当成整理结果。

## 内容分类：主题、类型、标签分别承担不同职责

主题回答“属于哪个技术领域”，采用最多两级的主分类。每篇笔记只有一个主位置；跨领域关联通过标签及链接表达。子分类随真实内容增长，只建立有内容支撑的目录。

| 主分类         | 建议子分类                                                                | 现有内容线索                                        |
| -------------- | ------------------------------------------------------------------------- | --------------------------------------------------- |
| Unity          | 基础与运行时、资源管理、功能开发、调试与性能、构建与发布、原生交互        | Addressables、ECS、HybridCLR、WebGL、打包与插件开发 |
| Android        | Framework 与组件、Jetpack、存储与网络、调试与性能、构建与发布、调试与安全 | Handler、Activity、MMKV、ANR、Gradle、Native 崩溃   |
| 编程语言与基础 | C#、Java 与 JVM、Kotlin、数据结构与算法、设计与架构                       | C#、集合、并发、JMM、算法、设计模式                 |
| 跨平台与 Web   | Flutter / Dart、Web、其他跨平台方案                                       | Flutter、WebView、H5、跨平台框架对比                |
| 工程工具       | 编辑器、版本管理、构建自动化、脚本与数据处理                              | VSCode、Rider、Git、Jenkins、Python、批处理         |
| 图形与音视频   | 图形与渲染、图像处理、音视频                                              | OpenGL、GPUImage、FFmpeg、模型处理                  |
| 网络与系统     | 网络协议、网络调试、系统与环境                                            | HTTP、SSE、抓包工具、Linux、WSL                     |
| AI 与开发辅助  | 基础概念、辅助开发工具、实践记录                                          | AI 名词、Kiro、开发培训                             |

这是分类方向，不要求一次性把八类都放进首批导航。首批重点展示 Unity、Android、编程语言与基础、工程工具；其他已有内容完成整理后再加入。

笔记类型独立于主题，建议为：**原理概念、操作指南、问题排查、项目复盘、资料索引**。过程记录和待确认内容留在本地整理区，提炼后再选择合适类型。类型不是网站一级导航。

例子：

- Unity 修改默认 JDK 版本 → Unity / 构建与发布；操作指南；标签 Android、JDK、Gradle。
- VSCode 快捷键 → 工程工具 / 编辑器；操作指南；标签 VSCode。
- Handler 同步屏障 → Android / Framework 与组件；原理概念；标签 Handler、消息队列。
- SP 引发的 ANR → Android / 调试与性能；问题排查；标签 SharedPreferences、ANR。

## 原笔记如何分流

| 材料形态                     | 整理去向          | 处理方式                                             |
| ---------------------------- | ----------------- | ---------------------------------------------------- |
| 技术概念、指南、问题排查     | 笔记库            | 校验内容、统一标题、补充适用环境与来源               |
| 面试资料中的知识文章         | 笔记库            | 和同主题知识笔记比较后整理，必要时再提炼题目         |
| 独立且可回答的面试问题       | 面试练习          | 建立问题、答案和追问，关联作为知识来源的笔记         |
| 链接合集、书单、工具列表     | 笔记库 / 对应主题 | 标为资料索引，区分原创总结与外部参考                 |
| 周报、会议、需求、项目流水账 | 本地档案          | 保留原始材料；有可复用经验时提炼成问题排查或项目复盘 |
| 账号配置、个人与内部资料     | 本地档案          | 先审阅公开范围；公开稿与原始资料分别保存             |
| 含糊标题、空壳、过时记录     | 本地待整理清单    | 查阅正文后决定补充、归档或重写，不按标题自动丢弃     |

标题初分中的“优先整理候选”也不等于“可以公开”。本地原始备份与可发布内容是两份产物。

## 网站信息结构

```text
BetterSelf
├─ 笔记库（默认首页 /）
│  ├─ 分类浏览：主题 → 子分类
│  ├─ 笔记列表：类型、标签、关键词筛选
│  ├─ 最近阅读 / 我的收藏（仅笔记）
│  └─ 笔记详情：正文、图片、目录、适用范围与来源
│     ├─ 相关笔记
│     ├─ 加入 / 移出复习（用户主动操作）
│     └─ 关联面试题（确有题目时展示）
├─ 面试练习（/practice）
│  ├─ 按主题浏览题目
│  └─ 题目详情：问题、答案、追问、自评、关联笔记
├─ 我的复习（/review）
│  ├─ 复习中的笔记
│  ├─ 待巩固的题目
│  └─ 已完成 / 移出复习
└─ 全局工具
   ├─ 搜索：默认笔记；可切换“笔记 / 面试题”，分开计数
   └─ 设置与备份：主题、字号、安装、学习记录导入导出
```

桌面保留左侧主要导航；手机保留“笔记库 / 面试练习 / 我的复习 / 搜索”四个底部入口。设置与备份作为工具入口，不混入笔记分类。现有文章和题目直达链接保留兼容，稳定 ID 不因改分类或改名而变化。

### 笔记库首页

- 展示主题导航、笔记列表、最近阅读；收藏入口只显示笔记收藏。
- 列表显示标题、摘要、类型、标签和更新时间。筛选条件可以组合，空结果提供清除筛选入口。
- 面试题数量、自评进度、面试热身、本次练习聚焦只放在面试或复习区域。
- 分类和笔记数只统计实际进入网站的内容。本轮盘点的 494 篇不是网站已发布内容数。

### 笔记详情

- 首要任务是阅读与查阅。保留正文目录、字号、图片等比缩放、来源与适用范围。
- 收藏、阅读位置和复习状态分别保存；点击收藏不自动加入复习。
- 只有实际有关联题目时出现“关联面试题”，采用次级链接，不把练习作为每篇笔记的固定结尾。
- 不给普通个人笔记强制展示“示例代码待验证”。将“资料来源”“适用范围”“核验状态”按实际材料显示。

### 面试练习

- 只呈现结构化题目；来源于笔记的题目可以回到知识笔记。
- 原有面试资料的长文先整理成笔记，再按需要拆出独立题目，避免双份长答案长期分叉。
- 题目自评属于练习行为。用户明确标记“不会 / 模糊”可视作加入待巩固队列，界面需说明该结果。

### 我的复习

- 是个人状态视图，不是第三个内容仓库。每项指向原笔记或原题目，不复制内容。
- 笔记只因主动加入而出现；阅读、收藏、首次导入不会自动创建复习任务。
- 笔记与题目在独立标签页展示。无任务时显示空状态，不能以“全部题目”代替真实复习队列。
- 首次先做手动加入、完成和移出，不引入自动排期或间隔重复算法。

## 需要调整的数据与实现

| 当前状态                                    | 下一轮调整                                                                   | 兼容要求                                                               |
| ------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 文章只有 topic 和 tags                      | 增加稳定分类 ID、子分类和笔记类型；保留主题展示名                            | 旧文章可通过映射补齐，ID 保持不变                                      |
| 原笔记目录没有迁移索引                      | 本地保存 sourceId → 网站笔记 ID 的映射、原路径、合并关系、原始文件与资源清单 | 私人原路径和原始资料不编译进公开搜索数据                               |

| 所有来源都强制为 HTTPS 链接                 | 区分个人记录与外部文档来源                                                   | 不为通过校验而编造外部链接                                             |
| 收藏、掌握程度和阅读记录共用 LearningRecord | 显式增加复习加入状态，内容类型保留 article/question 内部值                   | 新增备份格式迁移，读入旧记录时保留收藏、自评与进度；普通笔记不自动入队 |

分类、来源和复习数据的调整先于批量导入；不为迁移临时绕过现有校验。

## 比较与去重规则

1. 标题规范化只产生候选组；同名不自动合并，跨语言、平台、版本的内容可并存。
2. 正文比较区分完全重复、部分重叠、版本演进、相同主题不同用途。图片、附件和链接也纳入核对。
3. 需要合并时选择一篇规范笔记作为目标，保留全部来源 ID 与原始备份；独有案例和图示保留。
4. 概念笔记与问题排查通常互相链接；即使主题相同，也不强行合成一篇长文。
5. 含糊标题在读过正文后重命名；本轮没有自动改动任何标题。
