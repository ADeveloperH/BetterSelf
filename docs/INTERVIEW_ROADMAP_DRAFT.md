## 收到个人材料后如何校准

1. 从简历、项目和周报提取职责、模块、协作边界、关键问题、采取措施与证据，保留用户确认的事实。
2. 对每项能力区分“实际负责且有证据”“参与但不能独立讲透”“需要补基础 / 做实验”“目标岗位暂不要求”。周报写到的事不自动等于独立完成。
3. 选两三个最有代表性的经历建立问题链：背景 → 约束 → 定位 → 决策 → 结果 → 代价 → 回归 / 回退。
4. 用目标职位要求找关键差距，再安排基础学习、最小验证和模拟问答；没有实际数据时明确缺口，不替用户编造收益。
5. 在目标岗位、职责归属、项目选择和训练难度需要取舍时咨询用户。公开网站只加入确认可公开、已经脱敏的案例，原始简历与周报留在本地整理区。

## 本次交付与暂缓范围

本次先把已有 5 道主问题的 10 条文字追问转为有答案的独立题目，保持原 5 个 ID 与学习记录。列表默认展示主问题，可选择专题和包含追问；收藏、自评筛选与搜索可以直接找到追问。追问详情延续“先思考再揭示”，支持单独收藏、自评和复习，返回保留父页状态。

此前提出的“8 主问题 + 16 追问，共 24 题”只作为候选批次。本次没有提前增加其中 3 组专项场景；等个人材料齐备后决定是否采用、如何调整，不将其当作已交付或最终计划。

## 复杂题的写法

一条问题链不把所有限制塞入第一问。第一问提供背景与初始证据，先让学习者给出排查路径；后续逐次加入低端机、旧版本、取消、迟到回调或发布失败等约束，要求修改原方案。每层均有独立参考答案，包含回答结构、实现要点、方案取舍、反例和验证证据。真实项目的实际结果与教学假设分别标注。
